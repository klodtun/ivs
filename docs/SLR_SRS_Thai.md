# ข้อกำหนดความต้องการของระบบ (SRS) — Smart Lantern Recovery บน iVS

เอกสารฉบับนี้เป็นข้อกำหนดความต้องการของระบบประเมิน ติดตาม และเก็บกู้โคมลอย
(Smart Lantern Recovery หรือ SLR) สำหรับงานยี่เป็งและเทศกาลโคมลอยขนาดใหญ่
โดยติดตั้งเป็นแอปบนแพลตฟอร์ม iVS (Internal Vibe Server) ของผู้จัดงานเอง

> แหล่งอ้างอิง: จัดทำจากเอกสารข้อกำหนดทางเทคนิคฉบับร่าง (Technical Specification)
> ที่ผู้จัดทำโครงการส่งมอบ ร่วมกับโจทย์ตั้งต้นเรื่องการสร้างความมีส่วนร่วมของผู้ร่วมงาน
> และข้อจำกัดจริงของ iVS ในคลังโค้ดนี้ (เครื่องเป้าหมาย RAM 4 ถึง 8 GB, Caddy เป็นตัวรับ
> ทราฟฟิกหน้าบ้าน) เอกสารนี้ **แทนที่** ข้อกำหนดในฉบับร่างเฉพาะจุดที่ระบุว่า "ปรับจากฉบับร่าง"
> ส่วนที่ไม่ได้กล่าวถึงให้ถือตามฉบับร่างเดิม

## 1. สรุปสำหรับผู้บริหาร

| หัวข้อ | สาระสำคัญ |
| --- | --- |
| เป้าหมาย | ให้ผู้จัดงานรู้ล่วงหน้าว่าโคมน่าจะตกบริเวณใด ส่งทีมเก็บกู้ได้ตรงจุด มีหลักฐานการเก็บและกำจัดที่ตรวจสอบได้ และให้ผู้ร่วมงานเห็นผลลัพธ์นั้นด้วยตนเอง |

| กลุ่มเป้าหมาย | งานยี่เป็งและเทศกาลโคมลอยขนาดใหญ่ ออกแบบให้รองรับหลายองค์กรตั้งแต่ต้น |
| รูปแบบการติดตาม | การคาดการณ์จุดตกเป็นหลัก GPS ติดโคมเป็นส่วนเสริมในระยะที่ 2 |
| แพลตฟอร์ม | Mobile App (iOS และ Android) สำหรับเจ้าหน้าที่, Web Admin สำหรับผู้จัดงาน และหน้าสาธารณะบนเว็บสำหรับผู้ร่วมงาน (ไม่ต้องติดตั้งแอป) |
| การแบ่งระยะ | (1) แผนที่ ข้อมูลลม พื้นที่ และการเก็บกู้แบบไม่มีสัญญาณ, (2) แบบจำลองจุดตกและหน้าสาธารณะ, (3) GPS ติดโคมและการสอบเทียบแบบจำลองจากข้อมูลจริง |
| ระยะเวลาโดยประมาณ | ระยะที่ 1 และ 2 ประมาณ 12 สัปดาห์ (ตามแผน 6 รอบการพัฒนาในฉบับร่าง) ระยะที่ 3 ขึ้นกับการได้อุปกรณ์และการอนุญาต |
| ความเสี่ยงหลัก | แบบจำลองยังไม่ผ่านการสอบเทียบ, สัญญาณมือถือหนาแน่นในคืนงาน, การอนุญาตด้านการบินและการปล่อยโคม, สิทธิ์ใช้ข้อมูลลมเชิงพาณิชย์ |

## 2. ขอบเขตที่ยืนยันแล้ว

### 2.1 อยู่ในขอบเขต

1. กำหนดพื้นที่จัดงาน พื้นที่ปล่อย จุดปล่อย พื้นที่ห้าม และพื้นที่ค้นหา ด้วยรูปหลายเหลี่ยม เส้น และหมุด
2. กำหนดจำนวนโคมและรอบการปล่อย บันทึกจำนวนที่ปล่อยจริง
3. ดึงข้อมูลลมจาก 2 ถึง 3 แหล่ง แสดงซ้อนกันบนแผนที่ เปิดปิดทีละชั้นได้ และเปรียบเทียบเป็นตัวเลขได้
4. จำลองจุดตกแบบ Monte Carlo และแสดงเป็นพื้นที่ความน่าจะเป็น ไม่ใช่จุดเดียว
5. มอบหมายพื้นที่ค้นหาให้ทีมภาคสนาม
6. บันทึกการพบ การจัดเก็บ และการกำจัดโคม พร้อมภาพถ่าย พิกัด เวลา และค่า SHA-256 ทำงานได้โดยไม่มีสัญญาณ
7. หน้าสาธารณะสำหรับผู้ร่วมงาน และการแจ้งพบโคมโดยประชาชน (หัวข้อ 5)
8. บัญชีคาร์บอนและกิจกรรมปลูกป่าชดเชย (หัวข้อ 6)
9. รับพิกัดจากอุปกรณ์ GPS ผ่านตัวแปลงรูปแบบข้อมูล (ระยะที่ 3)

### 2.2 นอกขอบเขต

1. การรับรองว่าพื้นที่ปล่อยปลอดภัย ผลการจำลองใช้ประกอบการวางแผนเท่านั้น ไม่ใช้แทนการอนุญาตจากหน่วยงานรัฐ
2. การติดตามโคมทุกดวงแบบเวลาจริง
3. การออกคาร์บอนเครดิตเอง ระบบทำหน้าที่บันทึกและรายงาน ไม่ใช่ผู้รับรอง
4. การจัดจำหน่ายบัตรหรือรับชำระเงิน

## 3. ผู้ใช้และสิทธิ์

| บทบาท | ช่องทาง | สิทธิ์หลัก |
| --- | --- | --- |
| ผู้ดูแลองค์กร | Web Admin | จัดการผู้ใช้ กิจกรรม และการตั้งค่าทั้งหมดขององค์กร |
| ผู้บัญชาการงาน | Web Admin | กำหนดพื้นที่ รอบปล่อย สั่งจำลอง มอบหมายงาน อนุมัติบันทึกการปล่อยจริง |
| หัวหน้าทีมภาคสนาม | Mobile App | ดูพื้นที่ของทีม มอบหมายงานย่อย ตรวจยืนยันรายงานจากประชาชนในพื้นที่ |
| เจ้าหน้าที่ภาคสนาม | Mobile App | ดูพื้นที่ที่ได้รับมอบ บันทึกการพบ การจัดเก็บ และถ่ายภาพหลักฐาน |
| เจ้าหน้าที่สิ่งแวดล้อม | Web Admin | บันทึกการกำจัดหรือรีไซเคิล บันทึกกิจกรรมปลูกป่า ดูแลบัญชีคาร์บอน |
| ผู้ร่วมงานและประชาชน | หน้าสาธารณะ | ดูสถิติ แจ้งพบโคม ลงชื่อร่วมกิจกรรมปลูกป่า ไม่ต้อง Login |

ทุกการกระทำของบทบาทที่ Login ต้องมีบันทึกตรวจสอบ (ตาราง `audit_logs`)

## 4. ข้อกำหนดเชิงหน้าที่

รหัสข้อกำหนดใช้รูปแบบ `FR-หมวด-ลำดับ` ระดับความสำคัญ: จำเป็น / ควรมี / มีได้

### 4.1 กิจกรรมและพื้นที่ (FR-GIS)

| รหัส | ข้อกำหนด | ระดับ |
| --- | --- | --- |
| FR-GIS-01 | สร้างกิจกรรม กำหนดวันเวลาและขอบเขตงานเป็นรูปหลายเหลี่ยม | จำเป็น |
| FR-GIS-02 | วาด แก้ไข และลบรูปหลายเหลี่ยม เส้น และหมุด บนแผนที่ทั้งใน Web Admin และ Mobile App | จำเป็น |
| FR-GIS-03 | กำหนดพื้นที่ห้ามพร้อมระดับความเสี่ยง โดยมีชั้นข้อมูลตั้งต้นของแนวขึ้นลงสนามบินที่ผู้ดูแลนำเข้าได้ | จำเป็น |
| FR-GIS-04 | ระบบปฏิเสธจุดปล่อยที่อยู่นอกพื้นที่ปล่อยหรืออยู่ในพื้นที่ห้าม | จำเป็น |
| FR-GIS-05 | นำเข้าและส่งออก GeoJSON | ควรมี |
| FR-GIS-06 | จัดการชั้นข้อมูล เปิดปิด ปรับความโปร่งใส และเรียงลำดับซ้อนทับได้ | จำเป็น |

### 4.2 โคมและรอบปล่อย (FR-LAN)

| รหัส | ข้อกำหนด | ระดับ |
| --- | --- | --- |
| FR-LAN-01 | กำหนดประเภทโคม ขนาด น้ำหนัก น้ำหนักเชื้อเพลิง เวลาเผาไหม้ และวัสดุ | จำเป็น |
| FR-LAN-02 | สร้างรอบปล่อย ระบุจุดปล่อย ประเภทโคม จำนวนตามแผน และเวลาตามแผน | จำเป็น |
| FR-LAN-03 | บันทึกจำนวนและเวลาปล่อยจริง โดยผู้บัญชาการงานยืนยัน | จำเป็น |
| FR-LAN-04 | สร้างรหัส QR ต่อรอบปล่อย (ค่าตั้งต้น) หรือต่อโคมแต่ละดวง (เลือกได้) เพื่อพิมพ์ติดโคม | จำเป็น |

**เหตุผลของ FR-LAN-04:** QR บนตัวโคมทำให้ผู้พบโคมสแกนแจ้งได้ทันที และผูกการพบกลับไปยังรอบปล่อยได้ถูกต้อง
ซึ่งช่วยทั้งการเก็บกู้และการสอบเทียบแบบจำลอง โดยไม่ต้องติดอุปกรณ์อิเล็กทรอนิกส์

### 4.3 ข้อมูลลม (FR-WX) — ปรับจากฉบับร่าง

| รหัส | ข้อกำหนด | ระดับ |
| --- | --- | --- |
| FR-WX-01 | ดึงลมทั้งระดับผิวพื้น (10, 80, 120, 180 เมตร) และระดับความกดอากาศ 1000, 975, 950, 925, 900 และ 850 hPa | จำเป็น |
| FR-WX-02 | แสดงแหล่งข้อมูล ชื่อแบบจำลอง เวลารอบคำนวณของแบบจำลอง และเวลาที่ข้อมูลมีผล ทุกครั้งที่แสดงค่า | จำเป็น |
| FR-WX-03 | เปรียบเทียบได้เฉพาะค่าที่เวลาและระดับความสูงตรงกัน หากไม่ตรงต้องประมาณค่าก่อนและแสดงว่าเป็นค่าประมาณ | จำเป็น |
| FR-WX-04 | แสดงลูกศรทิศทางลมและเส้นการไหลของลมซ้อนบนแผนที่ แยกสีตามแหล่ง | จำเป็น |
| FR-WX-05 | แจ้งเตือนเมื่อข้อมูลเก่ากว่าเกณฑ์ (ค่าตั้งต้น 6 ชั่วโมงนับจากรอบคำนวณ) หรือเมื่อแหล่งต่าง ๆ ให้ทิศทางลมต่างกันเกินเกณฑ์ (ค่าตั้งต้น 45 องศา) | จำเป็น |
| FR-WX-06 | เก็บข้อมูลดิบทุกครั้งที่ดึง เพื่อทำซ้ำผลการจำลองย้อนหลังได้ | จำเป็น |

**แหล่งข้อมูลที่เสนอ (แทนชุด Open-Meteo / NOAA / Windy ในฉบับร่าง)**

| ลำดับ | แหล่ง | บทบาท | ข้อควรทราบ |
| --- | --- | --- | --- |
| 1 | Open-Meteo โดยเลือกแบบจำลองแยกกันอย่างน้อย 2 แบบ เช่น ECMWF IFS และ NOAA GFS | แหล่งหลักของลมระดับความกดอากาศ | แบบจำลองต่างกันเป็นอิสระต่อกันในเชิงการคำนวณ แม้ผ่านผู้ให้บริการรายเดียว ต้องแสดงชื่อแบบจำลองเสมอ รุ่นฟรีห้ามใช้เชิงพาณิชย์ |
| 2 | MET Norway (api.met.no) | แหล่งเปรียบเทียบลมผิวพื้นจากผู้ให้บริการอีกราย | เปิดให้ใช้ฟรีโดยต้องระบุที่มาและส่งชื่อโปรแกรมในการเรียก ให้ข้อมูลลมผิวพื้นเป็นหลัก ไม่มีลมระดับความกดอากาศ |
| 3 | กรมอุตุนิยมวิทยา | แหล่งในประเทศ เพิ่มความเชื่อมั่นต่อหน่วยงานรัฐ | ต้องลงทะเบียนขอสิทธิ์ ตรวจสอบรายการตัวแปรที่เปิดให้ก่อนพัฒนา ข้อมูลตรวจวัดอากาศชั้นบนใช้สอบเทียบแบบจำลองได้ |

Windy เก็บไว้เป็นทางเลือกในระยะหลัง เพราะรุ่นฟรีใช้ได้เฉพาะการพัฒนา
ก่อนใช้งานจริงต้องตรวจสอบเงื่อนไขของทุกแหล่งอีกครั้ง หากผู้จัดงานเก็บค่าบัตรหรือมีผู้สนับสนุน ให้ถือว่าเป็นการใช้เชิงพาณิชย์

### 4.4 การจำลองจุดตก (FR-PRD)

| รหัส | ข้อกำหนด | ระดับ |
| --- | --- | --- |
| FR-PRD-01 | สั่งจำลองต่อรอบปล่อย ทำงานเบื้องหลัง ตอบกลับทันทีพร้อมรหัสงาน | จำเป็น |
| FR-PRD-02 | จำลองแต่ละตัวอย่างเป็น 3 ช่วง คือ ลอยขึ้นระหว่างเผาไหม้, ลอยตัวช่วงเชื้อเพลิงใกล้หมด และร่วงลงหลังดับ โดยเคลื่อนตามลมที่ประมาณค่าตามความสูงและเวลา | จำเป็น |
| FR-PRD-03 | สุ่มค่าความไม่แน่นอนของ อัตราลอยขึ้น เวลาเผาไหม้ อัตราร่วง และลมจากความต่างระหว่างแหล่ง | จำเป็น |
| FR-PRD-04 | สร้างพื้นที่ความน่าจะเป็น 3 ระดับ (50, 80 และ 95 เปอร์เซ็นต์ของตัวอย่าง) เป็น MultiPolygon | จำเป็น |
| FR-PRD-05 | ประมาณจำนวนโคมที่คาดว่าตกในแต่ละพื้นที่ค้นหาและแต่ละพื้นที่ห้าม | จำเป็น |
| FR-PRD-06 | แสดงสถานะ ข้อมูลไม่พอ / ข้อมูลลมเก่า / อยู่นอกช่วงที่สอบเทียบแล้ว / ความไม่แน่นอนสูง และไม่วาดพื้นที่เมื่ออยู่ในสถานะ "ข้อมูลไม่พอ" | จำเป็น |
| FR-PRD-07 | เก็บรุ่นแบบจำลอง ค่าตั้งต้น ค่าสุ่มเริ่ม และรอบข้อมูลลมที่ใช้ เพื่อทำซ้ำผลได้ | จำเป็น |
| FR-PRD-08 | เทียบจุดที่พบจริงกับพื้นที่คาดการณ์หลังงาน และรายงานสัดส่วนที่ตกในแต่ละระดับ | ควรมี |

**ค่าทางกายภาพของโคม:** ทั้งอัตราลอยขึ้น เวลาเผาไหม้ และอัตราร่วง ต้องได้จากการวัดจริงกับโคมรุ่นที่ใช้ในงาน
ระบบต้องไม่มีค่าตั้งต้นที่ดูเหมือนผ่านการตรวจสอบแล้ว หากไม่ได้กรอกค่าเหล่านี้ ให้ระบบอยู่ในสถานะ "ข้อมูลไม่พอ"

### 4.5 การเก็บกู้และหลักฐาน (FR-REC) — ปรับจากฉบับร่าง

| รหัส | ข้อกำหนด | ระดับ |

## 6. บัญชีคาร์บอนและกิจกรรมปลูกป่า (หมวดงานใหม่ที่ 13 ต่อ)

### 6.1 หลักการ

1. **แยกตัวเลข 3 ชุดเสมอ** คือ ปริมาณที่ประมาณว่าปล่อย ปริมาณที่ชดเชยจากกิจกรรมที่เกิดขึ้นแล้ว และปริมาณที่ประมาณว่าจะชดเชยได้ในอนาคต ห้ามรวมเป็นตัวเลขเดียว
2. **ทุกค่าสัมประสิทธิ์ต้องมีแหล่งอ้างอิง** โดยเก็บแหล่งอ้างอิง ปี และผู้อนุมัติค่าไว้ในระบบ ให้ใช้ค่าที่องค์การบริหารจัดการก๊าซเรือนกระจก (อบก.) เผยแพร่เป็นลำดับแรก
3. **นับการชดเชยเฉพาะต้นไม้ที่ปลูกจริง** มีพิกัด ภาพ วันที่ และการติดตามอัตรารอด
4. **ถ้อยคำบนหน้าสาธารณะต้องตรงกับสถานะจริง** หากยังไม่ผ่านการรับรอง (เช่น โครงการ T-VER) ให้ใช้คำว่า "กิจกรรมปลูกป่าเพื่อชดเชย" ห้ามใช้คำว่า "คาร์บอนเป็นศูนย์" หรือ "ชดเชยครบแล้ว"

### 6.2 วิธีคำนวณ

- **ปริมาณที่ปล่อย** = จำนวนโคมที่ปล่อยจริง × น้ำหนักเชื้อเพลิงต่อดวง × ค่าการปล่อยก๊าซต่อหน่วยน้ำหนักเชื้อเพลิง
  และเพิ่มส่วนของการขนส่งหรือการกำจัดได้เมื่อมีข้อมูล
- **ปริมาณที่ชดเชยแล้ว** = ผลรวมของ (จำนวนต้นที่รอด × อัตราการดูดซับต่อต้นต่อปีตามชนิดพันธุ์ × จำนวนปีที่ติดตามแล้ว)
- **ปริมาณที่คาดว่าจะชดเชย** = ประมาณการตามระยะเวลาโครงการ แสดงแยกและระบุว่าเป็นประมาณการ

## 7. สถาปัตยกรรมที่ปรับให้เหมาะกับ iVS — ปรับจากฉบับร่าง

### 7.1 เหตุผลที่ต้องปรับ

ฉบับร่างกำหนดไว้ 12 คอนเทนเนอร์ ขณะที่ iVS Free ออกแบบให้ทำงานบนเครื่อง RAM 4 ถึง 8 GB
ร่วมกับแอปอื่นบนเครื่องเดียวกัน และ iVS มี Caddy เป็นตัวรับทราฟฟิกหน้าบ้านอยู่แล้ว
การมี Nginx ของตนเองซ้อนอีกชั้นจึงไม่จำเป็น ระยะที่ 1 และ 2 จึงรวมเหลือ 6 คอนเทนเนอร์

### 7.2 คอนเทนเนอร์ระยะที่ 1 และ 2

| คอนเทนเนอร์ | หน้าที่ | รวมจากฉบับร่าง | เพดานหน่วยความจำที่เสนอ |
| --- | --- | --- | --- |
| `slr-api` | API ที่เขียนด้วย Node.js, การยืนยันตัวตน, การดึงข้อมูลลม, งานเบื้องหลังด้วย BullMQ, รับ GPS ผ่าน HTTPS | slr-mobile-api, slr-auth, slr-weather, slr-worker, slr-gps | 512 MB |
| `slr-web` | Web Admin และหน้าสาธารณะ สร้างเป็นไฟล์คงที่ด้วย Next.js | slr-web | 128 MB |
| `slr-prediction` | การจำลองด้วย Python และ NumPy รับงานจากคิว | slr-prediction | 1 GB |
| `slr-db` | PostgreSQL + PostGIS | slr-db | 768 MB |
| `slr-redis` | คิวงานและแคช | slr-redis | 128 MB |
| `slr-storage` | MinIO สำหรับภาพหลักฐาน | slr-storage | 256 MB |

รวมเพดานประมาณ 2.8 GB ตัวเลขนี้เป็นค่าตั้งต้นสำหรับการวัดจริงในรอบการพัฒนาที่ 1 ยังไม่ใช่ค่าที่ยืนยันแล้ว
ส่วน `slr-mqtt` จะเพิ่มในระยะที่ 3 เมื่อเลือกอุปกรณ์ GPS ที่ใช้ MQTT แล้ว และ Caddy ของ iVS ใช้แทน `slr-proxy`

### 7.3 การรับภาระในคืนงาน

1. **หน้าสาธารณะ** อ่านจากไฟล์สรุปที่สร้างใหม่ทุก 30 ถึง 60 วินาที ให้ Caddy ส่งพร้อมแคช
   ไม่ให้คำขอแต่ละครั้งไปถึงฐานข้อมูล หากคาดว่าผู้เข้าชมสูงมาก ให้เผยแพร่ไฟล์สรุปผ่านบริการกระจายเนื้อหาภายนอก
2. **API ของเจ้าหน้าที่** แยกเส้นทางและจำกัดอัตราแยกจากหน้าสาธารณะ
3. **ต้องวัดแบนด์วิดท์ขาขึ้น** ของสถานที่ติดตั้งเครื่อง iVS ก่อนรับปากเป้าหมาย 500 ผู้ใช้พร้อมกันในฉบับร่าง
   ภาพย่อขนาดละ 200 KB จาก 100 เครื่องพร้อมกันใช้ประมาณ 20 MB ต่อรอบ ซึ่งเครือข่ายบ้านหรือสำนักงานทั่วไปรับได้
   แต่ภาพต้นฉบับขนาดหลาย MB ต้องรอส่งภายหลัง (FR-OFF-03)

### 7.4 HTTPS

แอปบน iOS ไม่ยอมเชื่อมต่อ API ที่เป็น HTTP ล้วน และหน้าสาธารณะต้องใช้กล้องกับพิกัดของเบราว์เซอร์ ซึ่งทำงานเฉพาะบน HTTPS
- **ช่วงพัฒนาและทดสอบ:** เปิด Tunnel ในหน้า iVS เพื่อให้ได้ที่อยู่ HTTPS ที่มือถือเชื่อถือ
- **ใช้งานจริง:** ตั้งค่า Caddy ของ iVS ด้วยโดเมนจริงและใบรับรองอัตโนมัติ

## 9. กฎหมาย ความปลอดภัยการบิน และ PDPA

### 9.1 เงื่อนไขก่อนอนุมัติการปล่อยในระบบ

ระบบต้องไม่ให้บันทึกการปล่อยจริง (FR-LAN-03) จนกว่าผู้บัญชาการงานจะแนบหรือยืนยันรายการต่อไปนี้

1. หนังสืออนุญาตหรือประกาศของจังหวัดและองค์กรปกครองส่วนท้องถิ่นที่เกี่ยวข้อง
2. ผลการประสานกับหน่วยงานด้านการบิน ได้แก่ สำนักงานการบินพลเรือนแห่งประเทศไทย (กพท.)
   และบริษัท วิทยุการบินแห่งประเทศไทย จำกัด เรื่องช่วงเวลาและพื้นที่ปล่อย
3. แผนเฝ้าระวังไฟและเบอร์ติดต่อหน่วยดับเพลิงในพื้นที่คาดการณ์ระดับ 95 เปอร์เซ็นต์

ระบบเก็บรายการนี้เป็นหลักฐานประกอบเท่านั้น ไม่ได้ตรวจสอบความถูกต้องทางกฎหมายแทนผู้จัดงาน

### 9.2 GPS ติดโคม

ก่อนติดอุปกรณ์กับโคมที่ปล่อยจริง ต้องผ่านทุกข้อต่อไปนี้
- ได้ความเห็นจากหน่วยงานด้านการบินว่าทำได้ เพราะเป็นการเพิ่มวัตถุอิเล็กทรอนิกส์และแบตเตอรี่ให้วัตถุลอยอากาศ
- ทดสอบว่าน้ำหนักที่เพิ่มไม่ทำให้โคมลอยต่ำหรือเสียการทรงตัว
- ทดสอบความร้อนของแบตเตอรี่ใกล้เปลวไฟ
- มีแผนเก็บคืนอุปกรณ์ทุกตัว (อุปกรณ์ที่ไม่ได้คืนนับเป็นขยะอิเล็กทรอนิกส์)

### 9.3 PDPA

| ข้อมูล | ฐานทางกฎหมายที่เสนอ | ระยะเวลาเก็บที่เสนอ | มาตรการ |
| --- | --- | --- | --- |
| บัญชีและตำแหน่งเจ้าหน้าที่ | สัญญาหรือประโยชน์โดยชอบด้วยกฎหมาย | ตำแหน่งระหว่างปฏิบัติงาน 90 วัน | เก็บตำแหน่งเฉพาะช่วงที่อยู่ในกะ |
| ภาพหลักฐาน | ประโยชน์โดยชอบด้วยกฎหมาย | 1 ปีหลังงาน | เบลอใบหน้าและป้ายทะเบียนก่อนเผยแพร่ |
| รายงานจากประชาชน | ความยินยอม | ภาพและพิกัด 1 ปี ช่องทางติดต่อตามที่ขอรับแจ้ง | ช่องทางติดต่อเข้ารหัส ลบอัตโนมัติตาม `delete_after` |
| ผู้ลงชื่อร่วมปลูกป่า | ความยินยอม | จนจบโครงการปลูก | ถอนความยินยอมได้จากลิงก์ในข้อความแจ้ง |

ระยะเวลาข้างต้นเป็นข้อเสนอเพื่อให้เจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคลของผู้จัดงานพิจารณา
และต้องจัดทำบันทึกรายการกิจกรรมการประมวลผล (ROPA) ตามแนวทางเดียวกับแผน Mail Server ของ iVS

## 13. ข้อตัดสินใจ

### 13.1 ยืนยันแล้ว

1. กลุ่มเป้าหมายคืองานยี่เป็งและเทศกาลโคมลอยขนาดใหญ่ ฐานข้อมูลรองรับหลายองค์กร
2. ใช้การคาดการณ์เป็นหลัก และ GPS ติดโคมเป็นส่วนเสริม
3. ใช้ Mobile App (iOS และ Android) ร่วมกับ Web Admin และเพิ่มหน้าสาธารณะบนเว็บ
4. ติดตั้งบน iVS แบบ Self-hosted
5. เพิ่มหมวดงานความโปร่งใสต่อสาธารณะและการชดเชยคาร์บอน

### 13.2 ข้อสมมติที่ใช้ดำเนินงาน (แก้ได้ด้วยการแจ้งครั้งเดียว)

1. QR ค่าตั้งต้นเป็นแบบต่อรอบปล่อย
2. เกณฑ์ข้อมูลลมเก่า 6 ชั่วโมง และเกณฑ์ทิศทางลมต่างกัน 45 องศา
3. แผนที่สาธารณะใช้ช่องตารางขนาด 500 เมตร
4. ระยะเวลาเก็บข้อมูลตามตารางในหัวข้อ 9.3

### 13.3 รอผู้จัดงานตัดสินใจ

| เรื่อง | ต้องตัดสินใจภายใน | ผลกระทบหากล่าช้า |
